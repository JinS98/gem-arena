# 아키텍처

> **현재 구현 범위:** 20~21일차 방 생성·참가·준비·시작은 제한된 Firestore 규칙으로 동작합니다. 22일차에는 공개/개인/서버 전용 게임 문서 분리와 Admin SDK 초기화 코드를, 23~24일차에는 인증·턴·규칙·버전·`actionId`를 검증하는 `submitAction` Callable을 로컬 에뮬레이터에서 검증했습니다. 25일차에는 방 시작 트리거와 공개/개인 문서 구독 게임판을, 26일차에는 `leaveRoom` 퇴장·기권과 같은 UID 복귀 경로를 로컬에서 연결했습니다. 현재 실제 프로젝트에는 신뢰할 수 있는 게임 초기화·턴 처리 백엔드가 배포되지 않았습니다.

```text
React + Zustand(UI) → Callable Functions(검증) → game-engine(순수 규칙)
          ↑                         ↓
     Firestore onSnapshot ← Transaction(서버 확정 상태)
```

- `apps/web`: 화면과 입력, 서버 상태 구독. 서버 게임 상태를 직접 수정하지 않음.
- `packages/game-engine`: Firebase/React와 독립적인 순수 규칙과 상태 전이.
- `functions`: 인증, 멤버십, 현재 턴, 게임 버전, 멱등성 검증.
- Firestore: 공개 게임 상태/서버 전용 상태/플레이어별 비공개 예약 분리.
- 동일 actionId 재전송과 expectedVersion 충돌을 트랜잭션으로 처리.
- 방 상태가 `waiting → playing`으로 바뀌면 `roomStarted`가 초기 문서를 생성한다. 클라이언트는 공개 문서와 본인 개인 문서의 버전이 일치할 때만 새 상태를 표시하고, 행동 응답 후 해당 버전의 구독을 기다린다.

## 1일차 운영 결정

- 대기 중 퇴장하면 멤버십을 제거한다. 방장 퇴장 시 가장 먼저 참가한 남은 플레이어에게 방장을 넘긴다.
- 연결 끊김은 퇴장으로 취급하지 않는다. 같은 익명 UID의 재접속을 기다리며 자동 기권·턴 타이머는 두지 않는다.
- 새로고침 시 Auth 로컬 지속성에서 UID를 복원한 뒤 방·공개·본인 개인 문서를 다시 구독한다. 초대 코드 재입력으로 이미 참가한 방에 돌아오면 기존 좌석을 사용한다.
- 진행 중 명시적 `leaveRoom`은 기권으로 처리한다. 보유 보석은 은행으로 돌려주고 카드·귀족·예약 카드는 게임에서 제외하며, 이후 턴에서 제외한다. 활성 플레이어가 한 명만 남으면 그 플레이어의 승리로 종료한다.
- `leaveRoom`은 신뢰 서버 트랜잭션에서 대기실 멤버십 또는 게임 상태·공개/개인 뷰를 원자적으로 갱신한다. 기권 표시를 유지해 중복 요청으로 버전이 다시 증가하지 않게 한다. 기권자는 결과 읽기만 허용한다.
- 27일차 권한 감사에서 방 생성·참가·준비·시작만 클라이언트 직접 쓰기를 허용하고, 게임 공개/개인 문서 및 서버 전용 문서의 클라이언트 쓰기를 거부하는 규칙을 에뮬레이터로 검증했다. 기권자는 결과를 읽지만 타인의 개인 문서를 읽지 못한다. 닉네임의 앞뒤 공백은 Firestore 직접 쓰기에서도 거부한다.
- 익명 UID를 잃으면 기존 자리를 복구하지 않는다. 새 UID의 진행 중 게임 참가도 허용하지 않는다. 이 경우 게임이 정체될 수 있으며 MVP의 알려진 한계다.
- 이 정책의 사용자 흐름·성공 기준은 [요구사항](requirements.md), API 입력·출력·실패 조건은 [Callable API 계약](api-contract.md)에 기록한다.
