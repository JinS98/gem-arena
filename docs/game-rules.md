# 기본판 규칙 명세

2일차에 게임 엔진 구현 목표를 확정한 문서다. [Space Cowboys의 기본판 규칙서](https://cdn.svc.asmodee.net/production-spacecowboys/uploads/2025/10/SCSPL01EN_SPLENDOR_RULES_LIGHT.pdf)를 참고했다. 온라인 플레이에 필요한 **게임별 적용 결정**은 아래에 별도로 표시한다. 카드·귀족의 명칭, 그림, 카드별 수치는 독자 자산으로 만든다.

## 준비

| 인원 | 일반 보석 은행 수량(색마다) | 황금 보석 | 공개 귀족 |
|---|---:|---:|---:|
| 2명 | 4 | 5 | 3 |
| 3명 | 5 | 5 | 4 |
| 4명 | 7 | 5 | 5 |

- 일반 보석은 흰색·파란색·초록색·빨간색·검은색 5종이다. 1·2·3단계 개발 카드 덱을 각각 섞고 단계마다 카드 4장을 공개한다. 공개 카드가 부족해지면 빈 자리를 유지한다.
- 게임 시작 시 첫 플레이어를 서버가 무작위로 정하고 참가 순서대로 턴을 돈다. **온라인 적용 결정:** 실물 규칙의 최연소 플레이어 선정 대신 사용한다. 첫 플레이어와 턴 순서는 게임 중 고정한다.
- 서버 전용 덱 순서와 비공개 예약 카드의 정체는 다른 플레이어에게 전송하지 않는다. 플레이어별 예약 카드 수는 공개한다.

## 한 턴의 순서

1. 현재 플레이어가 아래 기본 행동 중 정확히 하나를 선택한다. 모든 입력은 서버가 현재 게임 버전과 함께 검증한다.
2. 보석 보유량이 10개를 넘으면 초과분만큼 원하는 보석을 은행에 반환한다. 반환을 마칠 때까지 턴을 넘기거나 귀족을 받지 않는다. 황금 보석도 10개 한도에 포함한다.
3. 보유한 카드의 영구 할인으로 공개 귀족의 조건을 만족하면 최대 1명을 받는다. 여러 명이 가능하면 현재 플레이어가 한 명을 선택해야 한다. 귀족은 추가 기본 행동이 아니다.
4. 개발 카드와 귀족의 점수를 합산한 뒤 15점 이상이면 최종 라운드를 시작한다. 이 턴이 끝난 뒤 다음 활성 플레이어로 진행하거나 최종 결과를 확정한다.

| 기본 행동 | 입력 | 유효 조건과 결과 |
|---|---|---|
| 서로 다른 보석 받기 | 1~3개의 일반 보석 색 | 사용 가능한 색이 3종 이상이면 정확히 3종을 받는다. 3종 미만만 남았다면 남은 서로 다른 색에서 1~2종을 선택할 수 있다. 황금색·중복색·없는 색은 선택할 수 없다. |
| 같은 보석 2개 받기 | 일반 보석 색 하나를 2회 | 행동 직전 해당 색이 은행에 4개 이상 있어야 한다. 정확히 2개를 받는다. 황금 보석은 선택할 수 없다. |
| 카드 예약 | 공개 카드 ID 또는 비공개 덱 단계 | 예약 카드가 3장 미만이고 대상 카드가 있어야 한다. 공개 카드를 예약하면 그 자리를 같은 단계 덱에서 보충한다. 덱 맨 위를 예약하면 다른 플레이어에게 카드를 공개하지 않는다. 은행에 황금 보석이 있으면 1개를 받고, 없으면 카드만 예약한다. 예약 카드의 폐기는 불가하다. |
| 카드 구매 | 공개 카드 또는 본인 예약 카드 ID, 결제 보석 | 비용을 정확히 낼 수 있어야 한다. 사용한 보석은 은행으로 돌려주고, 카드를 공개 소유로 옮겨 영구 할인과 점수를 얻는다. 공개 카드를 샀으면 같은 단계 덱에서 보충한다. |

구매 시 색별 남은 비용은 `max(0, 카드 비용 - 해당 색 영구 할인)`이다. 플레이어는 `payment`에 일반 보석 5종과 황금 보석 수량을 제출하며, 모든 수량은 0 이상의 정수여야 한다. 가진 보석을 초과해 제출할 수 없다. 일반 보석과 황금 보석(아무 색 대신 사용)을 조합해 **남은 비용만 정확히** 낸다. 황금 보석은 해당 색의 일반 보석을 갖고 있어도 사용할 수 있다. 할인으로 비용이 0이면 보석을 사용하지 않는다. 할인 초과분에 대한 보석은 받지 않는다.

## 귀족·종료·승패

- 귀족은 구매·보석 획득·예약 자체가 아니라 **턴 종료 시** 공개된 귀족 중 영구 할인 조건을 만족하는 경우에만 받는다. 보유 보석이나 예약 카드 수는 조건에 포함하지 않는다.
- 15점 도달은 턴 종료 시 판정한다. 그 시점부터 첫 플레이어 기준 현재 라운드의 나머지 턴을 진행해 활성 플레이어 모두의 턴 수를 같게 만든다. 마지막 순서 플레이어가 15점에 도달했으면 즉시 종료한다.
- 개발 카드와 귀족의 총점이 가장 높은 플레이어가 승리한다. 동점이면 그중 구매한 개발 카드 수가 적은 플레이어가 승리한다. 그래도 같으면 공동 승리한다.
- [1일차 운영 정책](requirements.md#운영-정책)에 따라 진행 중 명시적으로 기권한 플레이어는 이후 턴·승패 판정에서 제외한다. 보유 보석은 은행으로 돌려주고 카드·귀족·예약 카드는 게임에서 제외한다. 활성 플레이어가 한 명만 남으면 즉시 승리한다. **온라인 적용 결정:** 최종 라운드 중 기권이 생겨도 남은 활성 플레이어의 해당 라운드 턴만 마친다.

## 입력·예외 케이스 표

모든 거부는 보석·카드·점수·턴·버전을 변경하지 않는다. `actionId`·`expectedVersion`·인증·멤버십 검증은 [API 계약](api-contract.md)에 따른다.

| ID | 입력/상황 | 결과 |
|---|---|---|
| R01 | 2/3/4명으로 게임 시작 | 색마다 일반 보석 4/5/7개, 황금 5개, 귀족 3/4/5명, 단계별 공개 카드 최대 4장 |
| R02 | 은행에 일반 보석 색이 3종 이상 있는데 1~2종만 요청 | `INVALID_ACTION`; 가능한 최대 3종을 받아야 함 |
| R03 | 은행에 일반 보석 색이 2종만 남아 1종 또는 2종 요청 / 1종만 남아 1종 요청 | 허용; 남은 수량이 0인 색이나 황금색 요청은 거부 |
| R04 | 같은 색 2개 요청, 은행 재고 3개/4개 | 3개면 거부, 4개면 허용 |
| R05 | 보석 획득·황금 수령 후 총 보유량 11~13개 | `discarding` 단계로 이동; 초과분을 정확히 반환하면 턴 마무리 |
| R06 | 예약 카드 3장 보유, 없는 공개 카드/빈 덱 예약 | `INVALID_ACTION`; 카드·은행 변경 없음 |
| R07 | 황금 보석이 0개인 상태에서 유효한 카드 예약 | 카드 예약 허용, 황금 보석 지급 없음 |
| R08 | 할인과 황금 보석으로 정확히 결제 가능한 카드 / 부족하거나 초과 결제한 카드 | 정확한 결제만 허용; 부족·초과 결제는 거부 |
| R09 | 공개 카드 구매·예약 후 해당 단계 덱 소진 | 빈 시장 칸 유지, 게임 계속 |
| R10 | 턴 종료 시 귀족 2명 이상 조건 충족 | `choosingNoble` 단계에서 1명 선택; 조건에 맞지 않는 귀족 선택은 거부 |
| R11 | 첫·중간·마지막 순서 플레이어가 15점 도달 | 해당 라운드의 남은 활성 플레이어 턴 후 종료; 마지막 순서면 즉시 종료 |
| R12 | 최고 점수 동점 / 카드 수까지 동점 | 구매 카드 수가 적은 플레이어 승리 / 공동 승리 |
| R13 | 잘못된 턴·종료 후 행동·중복 `actionId`·낡은 버전 | 상태 중복 변경 없음; API 계약의 오류 또는 이전 성공 응답 |
| R14 | 명시적 기권으로 활성 플레이어 1명만 남음 | 즉시 종료하고 남은 플레이어 승리 |
| R15 | 진행 중 기권자가 보석·카드·예약 카드를 보유 / 턴 마무리 대기 중 | 보석은 은행에 반환, 나머지 자산은 게임에서 제외; 미완료 턴을 취소하고 다음 활성 플레이어로 이동 |
| R16 | 현재 플레이어에게 합법 행동이 없음 / 합법 행동이 있음 | 없음: `PASS` 허용; 있음: `PASS` 거부. 전원 연속 `PASS`면 현 점수로 종료 |

**온라인 적용 결정:** 현재 플레이어에게 합법적인 기본 행동이 하나도 없으면 `PASS`를 허용한다. 합법 행동이 있으면 `PASS`는 거부한다. 모든 활성 플레이어가 연속으로 `PASS`하고 그 사이 자산·점수 상태 변화가 없으면 게임을 종료하고 현재 점수·동점 규칙으로 승자를 정한다. 기본판의 물리적 정체 상태를 온라인에서 끝낼 수 있게 하는 안전장치이며 엔진 구현 시 별도 행동과 테스트가 필요하다.

## 구현 현황

현재 엔진에는 보석 수량 계산·획득 가능 여부 검사 예시와 [정적 카드·귀족 목록](data-model.md#정적-게임-데이터-5일차)이 있다. 방·턴·카드 구매/예약·귀족 방문·종료 상태 전이와 위 예외 대부분은 아직 구현되지 않았다. 이 표의 통합 시나리오는 엔진과 서버 구현 일차에 실행한다.
