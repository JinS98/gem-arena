## 작업 기록
- 구현 내용: 시장 카드를 누르면 점수·보너스·할인 후 비용·보유 보석·황금 대체 수량을 보여주는 모달이 열린다. 선택한 일반 보석 수량에 따라 황금 필요량이 바뀌고 `canPayForCard`로 구매 가능 여부를 판단한다. 구매는 `buyCard`, 예약은 `reserveCard`를 사용한다. 시장 보충, 단계별 덱 수, 은행·보유 보석, 점수·영구 할인, 예약 카드 목록이 함께 갱신된다. 예약 카드도 모달에서 구매할 수 있다.
- 입력·예외: 현재 연습 턴에만 구매·예약할 수 있다. 결제 부족, 잘못된 카드, 예약 3장 초과는 모달 비활성화 또는 엔진 검증으로 거부한다. 예약으로 보석이 10개를 넘으면 기존 초과 반환 UI로 이어진다. 모달은 Escape·바깥 클릭·닫기 버튼으로 닫으며 키보드 포커스가 안에서 순환한다.
- 실행한 테스트/결과: `npm run typecheck`, `npm run build`, `npm test` 통과(엔진 71개). 브라우저에서 시장 구매·예약·예약 카드 구매, 결제 부족 카드 차단, 황금 대체 변경, 시장 보충과 덱 감소, 한 턴 한 행동 제한, 초기화를 확인했다. 390px 화면에서 모달 레이아웃을 확인했다.
- 이슈/의사결정: `/game/demo`는 고정 샘플 카드와 로컬에서 만든 연습용 덱을 사용한다. 이 상태는 실제 방의 서버 상태가 아니며 비공개 덱을 클라이언트에 전달하는 패턴으로 사용하지 않는다. 귀족 방문과 실제 턴 진행은 후속 UI·서버 연결 단계에서 처리한다.
- 다음 작업에 전달할 사항: 17일차 턴/결과 UI는 현재 로컬 `phase` 및 카드 행동 결과를 활용할 수 있다. 실제 대전은 서버가 확정한 공개/개인 상태와 액션 응답을 연결해야 한다.
