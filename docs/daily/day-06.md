## 입력·출력·예외 조건

- 입력: `createInitialGameState(playerIds, seed)`에 참가 순서대로 서로 다른 2~4명의 ID와 `0`~`4294967295`의 정수 시드를 전달한다. 시드는 호출 서버에서 예측하기 어렵게 생성한다.
- 출력: `phase: 'playing'`, `version: 0`, 0으로 초기화된 플레이어 자산·점수, 무작위 첫 턴, 인원별 은행·귀족과 단계별 시장·덱을 포함하는 `ServerGameState`. 동일 입력과 시드는 같은 상태를 반환한다.
- 예외: 잘못된 인원·빈/중복 ID·잘못된 시드는 `RangeError`로 거부한다. 이 함수는 순수 초기화이므로 인증·권한 검사는 방 시작 API에서 처리한다. 반환 상태에는 비공개 덱 순서가 있으므로 클라이언트에 직접 전송하면 안 된다.

## 작업 기록
- 구현 내용: 시드 기반 셔플과 인원별 은행·시장·덱·귀족·첫 턴 초기화 함수를 추가했다. README·데이터 모델·규칙 문서에 사용 조건을 반영했다.
- 실행한 테스트/결과: `npm test` 19개 통과(6일차 초기화 7개 포함), `npm run typecheck` 통과.
- 이슈/의사결정: 시드는 32비트 정수로 제한했다. 동일 시드 재현을 위해 셔플 순서를 1·2·3단계 카드, 첫 턴 선택, 귀족 순으로 고정했다. 첫 턴은 참가 순서를 유지한 채 `turnIndex`로 선택한다. 원본 정적 카드는 변경하지 않는다.
- 다음 작업에 전달할 사항: 방 시작 서버 함수에서 예측하기 어려운 시드를 만들고 필요하면 서버 전용으로 보관한다. `decks`는 비공개 상태에만 저장하고 공개 뷰로 보내지 않는다. 7일차부터 이 초기 상태에 순수 규칙을 적용한다.
