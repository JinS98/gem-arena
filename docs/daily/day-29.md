## 입력·출력·예외 조건

- 넓은 PC 화면에서 2~4인 상대 공개 상태와 귀족을 왼쪽에, 높이 제한 없는 시장을 중앙에, 은행·행동·내 현황을 오른쪽에 배치한다. 페이지에서 시장 카드를 세로로 탐색하는 동안 양쪽 자원 현황이 화면에 남는다. 내 패널은 간단 보기와 자세히 보기를 제공한다. 시장·예약 카드는 원본 그림의 2:3 비율을 유지한다. 카드 그림은 장식이며 숫자 비용과 보너스는 버튼 이름·텍스트로도 읽힌다.
- 모바일 320~390px에서는 페이지 자체의 가로 넘침 없이 상대와 단계별 시장 카드를 해당 목록 안에서 가로로 탐색한다. 보석 선택·덱 예약·카드 모달 조작을 계속 사용할 수 있다.
- 카드 모달을 열면 닫기 버튼으로 초점을 옮기고 Tab 초점을 모달 안에 유지한다. 닫으면 원래 카드로 초점을 돌린다. 귀족 선택 버튼은 점수와 필요한 할인 조건을 읽어 준다.
- 행동 성공 알림과 내 자원 강조는 Callable 성공 후 공개·개인 뷰가 확정 버전으로 구독된 다음에만 표시한다. 움직임 줄이기 설정에서는 애니메이션과 전환을 끈다. 방·게임판 구독 오류는 재연결 버튼을 제공한다.
- 보석 획득·예약·구매 시 행동 전에 은행 보석 또는 카드 보너스의 위치를 저장하고, 서버가 확정한 내 자원 변화가 있을 때만 해당 보석을 내 자원 칸으로 이동시킨다. 황금 보석이 소진된 예약에서는 이동을 표시하지 않는다. 넓은 화면에서는 카드 그림·비용·행동 버튼을 키우고 세로 스크롤을 허용한다.

## 검증 시나리오
1. Auth·Firestore·Functions 에뮬레이터와 Chrome에서 2·3·4인 방을 만들고, 1440×900 화면에서 세 시장 줄의 카드 4장씩, 2:3 그림 비율과 세로 스크롤을 확인한다.
2. 390px과 320px에서 문서의 가로 넘침이 없는지, 시장 줄을 내부에서 가로 탐색하는지 확인한다. 모바일에서 덱 예약을 제출하고 공개 예약 수가 증가하는지 확인한다.
3. 카드를 열 때 초점 이동, 마지막 버튼에서 Tab 순환, Escape 후 원래 카드로 초점 복귀를 확인한다. 움직임 줄이기 설정에서 카드 전환 시간이 0인지 확인한다.
4. 없는 방의 게임판·대기실에서 재시도 버튼이 표시되는지 확인한다. 서버 응답이 확정된 행동의 알림만 표시하고, 기존 동시 클릭·서버 권한 검증은 회귀 테스트로 확인한다.
5. 예약 황금 보석, 보석 받기 3개, 카드 구매 보너스가 서버 확정 후 출발지에서 내 자원으로 이동하는지 확인한다. 1800×900에서 카드 비율과 버튼 글자 크기를 확인하고, 움직임 줄이기에서는 이동 요소 없이 확정 수량이 표시되는지 확인한다.
6. Firestore 에뮬레이터 연결을 차단한 뒤 새 방 만들기에서 연결 오류 알림, 인라인 오류, 버튼 복구를 확인한다.

## 완료 기준
**PC에서 카드 그림 전체와 자원 정보를 세로 스크롤로 확인하고, 모바일에서 주요 행동·키보드 조작을 완료한다.**

## 작업 기록
- 구현 내용: 기존 단계별 2×2 시장을 PC에서 가로 4장씩 3단계로 재배치하고, 테이블 프레임·조명·카드 초점 강조를 추가했다. 5명까지 공개되는 귀족 영역과 상대·내 자원을 압축해 1440×900에 맞췄다. 모바일에서는 시장·상대 목록 내부만 가로 스크롤한다. 카드 모달 초점 순환·복귀, 귀족 조건 및 덱 예약 버튼 이름, 선택 모드 상태, 큰 터치 목표, 오류 재시도, 서버 확정 알림·움직임 줄이기를 추가했다.
- 실행한 테스트/결과: 에뮬레이터/Vite/Chrome에서 `verify-browser-reconnect.mjs`를 2·3·4인으로 실행해 모두 통과했다. 최종 스타일에서 1440×900의 내 자원 하단은 888px, 390px·320px에서는 페이지 가로 넘침이 없었다. 모바일 덱 예약, 키보드 모달, 움직임 줄이기와 오류 화면 재시도를 확인했다. 전체 모노레포 빌드와 `npm test`(엔진 84건·웹 1건)도 통과했다.
- 이슈·의사결정: 초기 4인 PC 배치에서는 귀족 5장의 높이 때문에 내 자원 하단이 921px로 내려갔다. 귀족 카드 높이를 줄여 900px 안에 맞췄다. 모바일에서는 한 화면에 모든 시장 카드가 들어가지 않으므로 단계별 카드 목록에 가로 스크롤을 허용했다. 예약 카드 내용은 본인 개인 문서에서만 보여 주며 상대에게는 개수만 표시한다.
- 다음 작업에 전달할 사항: 30일차에 2~4인 실제 완주, 화면 배율·실기기·읽기 비용을 점검한다. PC의 900px보다 낮은 화면이나 운영 Firebase 연결은 아직 검증하지 않았다.
- 사용자 피드백 후 보완: 멀티 게임판에도 로컬 게임판의 보석 이동 도우미를 연결했다. 행동 직전에 은행 보석·카드 보너스·귀족의 화면 위치를 저장하고, 서버 확정 버전에서 실제로 증가한 자원과 방문 귀족만 이동시킨다. 보석 수량·영구 할인·점수는 도착 시 갱신하며, 새 행동이나 페이지 이탈 시 진행 중인 이동을 취소한다. 1600px 이상에서는 시장 카드 높이, 비용 칩, 귀족 조건, 은행과 행동 버튼 글자를 키웠다. 1800×900 화면에서는 내 자원 패널까지 세로 스크롤이 필요하다.
- 추가 검증: 에뮬레이터 Chrome 2·3·4인 시나리오에서 예약 황금 보석, 일반 보석 3개, 구매 카드의 보너스 보석 이동을 확인했다. 움직임 줄이기에서는 예약 수량만 반영되고 이동 요소는 생기지 않았다. 1800px 카드 높이 150px 이상과 행동 글자 12px 이상, 1440×900 한 화면 배치, 320·390px 가로 넘침 없음도 확인했다. 전체 빌드와 엔진 84건·웹 1건 테스트가 통과했다.
- 후속 피드백 반영: 한 화면에 맞추던 시장 카드 높이 제한을 풀고 원본 그림의 600×900 비율을 적용했다. 내 예약 카드도 같은 비율로 확대했다. 1440×900의 한 화면 배치는 더 이상 목표가 아니며, 은행·행동 영역은 PC 스크롤 중에도 보이도록 고정했다. 새 방 요청 전에 로컬 Firestore 연결을 확인하고, 지연되는 요청은 8초 뒤 알림과 재시도 상태를 표시한다. 같은 생성 요청의 결과가 불명확하면 진행 중인 Promise를 재사용한다.
- 후속 검증: Chrome 2·4인에서 시장 카드의 2:3 비율, 320·390px 가로 넘침 없음, 방 생성 성공, Firestore 차단 시 브라우저 알림·인라인 오류·버튼 복구를 확인했다. 4인 1440×900의 내 자원 하단은 1448px로 세로 스크롤된다.
- 자원 현황 배치 보완: PC의 빈 양쪽 열을 사용해 귀족 아래 상대 공개 자원을 왼쪽, 은행·행동 아래 내 자원과 예약 카드를 오른쪽에 배치했다. 1251px 이상에서는 양쪽 현황이 시장 카드 스크롤을 따라오며, 더 좁은 화면에서는 카드 영역 위아래로 재배치된다. Chrome 에뮬레이터 2·3·4인에서 1800×900 시장 하단 스크롤에도 상대·은행·내 보석이 보이는지, 1100px에서 자원 패널과 시장의 가로 넘침이 없는지 확인했다.
- 내 패널 후속 조정: 상대 현황을 왼쪽에 유지하고 보유 보석을 색 이름·아이콘·수량의 2열 목록으로 표시해 4인 화면에서도 상대 3명을 한눈에 볼 수 있게 했다. 귀족은 중앙 시장 위로 이동했다. 1351px 이상 PC에서는 중앙 카드 영역만 내부 스크롤하도록 높이를 제한하고 그 아래 별도 내 현황 패널을 겹쳐 배치하되 카드를 가리지 않게 했다. 더 좁은 화면에서는 상대·시장·은행·내 패널을 순서대로 배치한다. 내 패널은 예약 카드까지 보이는 자세히 보기와 자원만 남기는 간단 보기로 전환하며 브라우저에 선택을 저장한다. Chrome 2·3·4인에서 중앙 카드와 내 패널이 겹치지 않는지, 4인 상대 3명 목록이 자체 스크롤 없이 보이는지, 토글·320/390px 모바일 행동을 확인했다.
- 카드 필드 복원: 중앙 시장의 `max-height`와 내부 세로 스크롤을 제거해 이전처럼 3단계 카드가 페이지 전체 높이로 이어지게 했다. 귀족을 다시 왼쪽으로, 내 현황을 은행·행동 아래 오른쪽으로 옮겼다. 상대 보석의 색 이름·아이콘·수량 표시와 내 현황의 간단/자세히 보기 및 저장된 선택은 유지한다. Chrome 2·3·4인에서 1440/1800px 카드 필드의 자연 높이, 페이지 스크롤 중 양쪽 보석 노출, 1251/1100px 및 모바일 가로 넘침, 토글 후에도 시장 높이가 변하지 않는 것을 확인했다.
