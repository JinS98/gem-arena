## 입력·출력·예외 조건

- 입력: `reduceGameAction(state, playerId, action)`은 현재 턴의 플레이어와 `GameAction`을 받는다. `playing`에서는 보석 획득·구매·예약·조건부 패스, `discarding`에서는 반환, `choosingNoble`에서는 선택만 허용한다.
- 출력: 매번 새 상태를 반환하고 정상 입력마다 `version`을 1 증가시킨다. 기본 행동 후 초과 보석 반환과 귀족 선택이 없으면 턴을 완료한다. 각 후속 입력도 별도 버전을 가진다.
- 예외: 불법 행동, 잘못된 단계·플레이어, 초과 보석을 둔 잘못된 `playing` 상태, 유효하지 않은 버전·연속 패스 수를 `RangeError`로 거부한다. API의 인증·`expectedVersion`·`actionId` 멱등성은 서버에서 처리한다.

## 작업 기록
- 구현 내용: `reduceGameAction`이 보석 획득·구매·예약·반환·귀족 선택·패스를 단계별로 연결한다. `consecutivePasses`를 추가하고 합법 행동 검사를 통해 패스와 정체 종료를 처리한다.
- 실행한 테스트/결과: `npm test` 71개 통과(13일차 9개 포함), `npm run typecheck` 및 `npm run build` 통과. 원본 상태와 보석 총량·카드 ID 보존을 테스트했다.
- 이슈/의사결정: 정상 요청 하나마다 버전을 한 번 올린다. 초과 보석 반환과 귀족 선택은 같은 턴의 추가 요청이다. 패스 중 귀족 방문으로 점수가 바뀌면 연속 패스 수를 0으로 되돌린다.
- 다음 작업에 전달할 사항: UI에서는 단계별로 가능한 행동만 보여준다. 서버는 인증·멤버십, `expectedVersion`, `actionId`를 reducer 호출 전후에 검증한다. 26일차 기권 처리에서는 활성 플레이어 수에 맞춰 패스 수와 턴 순서를 조정한다.
