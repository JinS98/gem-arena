## 작업 기록
- 구현 내용: 고정 3인 샘플을 엔진의 `ServerGameState`로 구성하고 보석 획득·반환, 카드 구매·예약, 귀족 선택을 `reduceGameAction`에 연결했다. 플레이어 패널과 턴 표시가 엔진의 현재 플레이어·점수·카드·보석을 보여준다. 기본 행동 후에는 `다음 플레이어 시작` 버튼으로 다음 차례를 연다. 귀족이 여러 명이면 자격 있는 귀족만 선택할 수 있고, 최종 턴 종료 시 승자·순위 결과 화면을 보여준다.
- 입력·예외: 현재 단계 외 행동은 UI에서 비활성화하고 reducer도 거부한다. 초과 보석 반환이나 귀족 선택이 끝나기 전에는 다음 차례로 넘어갈 수 없다. 귀족 선택 상황에는 자격 없는 귀족 하나를 포함해 버튼이 비활성화되는지 확인할 수 있다. 결과 화면의 새 연습 버튼은 샘플을 초기화한다.
- 실행한 테스트/결과: `npm run typecheck`, `npm run build`, `npm test` 통과(엔진 71개). 브라우저에서 3인 턴 전환, 카드 구매·예약 및 예약 카드 구매, 9개 보유 상황의 초과 반환, 귀족 2명 중 선택과 자격 없는 귀족 차단, 최종 턴 후 승자·순위, 재시작을 확인했다. 390px 모바일 폭에서 결과 화면을 확인했다. 기본 화면은 7점으로 복원하고 `귀족·종료 상황` 버튼에서 1단계 빨간 카드 한 장 구매 → 귀족 2명 중 선택 → 15점 즉시 종료를 검증했다.
- 이슈/의사결정: `/game/demo`의 전체 엔진 상태와 덱은 로컬 샘플 전용이며 실제 방 상태나 비공개 덱을 클라이언트에 전달하는 방식이 아니다. 기본 화면은 7점이고, `귀족·종료 상황` 버튼은 빨간 보너스가 2개, 점수가 11점인 마지막 턴 예시를 연다. 금색 테두리의 1단계 빨간 카드(+1점)를 구매하면 귀족 두 명의 조건을 동시에 만족하며 한 명 방문(+3점) 후 15점으로 종료한다. 다른 플레이어의 샘플 점수와 구매 카드는 화면 연습용으로 구성한다.
- 다음 작업에 전달할 사항: 18일차에는 초기 샘플뿐 아니라 2~4인 새 게임 생성부터 종료까지 한 판을 통합 검증한다. 이후 서버 연결에서는 서버가 확정한 공개·개인 상태와 액션 결과로 화면을 갱신한다.
