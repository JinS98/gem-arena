## 입력·출력·예외 조건

- 대기실의 시작 버튼은 방 상태를 `waiting`에서 `playing`으로 바꾼다. `roomStarted` Functions 트리거가 그 전이에서만 초기 서버·공개·개인 문서를 만든다.
- `/game/demo`는 기존 로컬 연습판이며 `/game/{roomCode}`가 멀티 게임판이다. 대기실에서 게임이 시작되면 멀티 게임판 링크가 나타난다.
- 방 참가자는 같은 `publicState`를 구독한다. 각자는 자신의 `privatePlayers/{uid}`만 구독한다. 두 문서의 버전이 다를 동안에는 마지막으로 일치했던 화면을 유지한다.
- 행동 요청은 현재 공개 버전을 `expectedVersion`으로 보내며 고유 `actionId`를 쓴다. 응답 후 해당 버전의 실시간 구독이 도착할 때까지 다음 입력을 잠근다. 네트워크 응답이 불확실하면 같은 요청 ID로 재시도한다.
- 방이 아직 시작 전이거나 초기화 문서가 없으면 대기 안내를 표시한다. 비참가자·읽기 오류는 게임판을 보여주지 않는다. 캐시 상태에서는 행동을 비활성화한다.

## 검증 시나리오
| 입력·조건 | 기대 결과 | 실행 결과 |
|---|---|---|
| 대기실 방 `waiting → playing` | 신뢰 서버가 초기 게임 문서 생성 | `npm run test:live-board` 통과 |
| 두 익명 참가자가 공개/개인 문서 구독 | 공개 뷰 동일, 개인 UID 각각 일치 | 통과 |
| 덱에서 비공개 예약 | 양측 공개 예약 수 +1, 카드 ID는 예약자에게만 표시 | 통과. 다른 참가자의 개인 문서 읽기 거부 |
| 다음 참가자가 보석 획득 | 양측 공개 뷰가 같은 버전으로 갱신 | 통과 |
| 기존 행동 API | 인증·턴·규칙·멱등성·경합 동작 유지 | `npm run test:actions` 통과 |
| 웹/Functions 빌드와 기존 규칙 | 타입·번들·엔진 동작 유지 | `npm run typecheck`, `npm run build`, `npm test` 통과 |

## 완료 기준
**두 독립 인증 세션에서 서버 확정 상태가 실시간으로 반영되고 비공개 예약 정보는 본인에게만 보인다.** 로컬 에뮬레이터 구독 검증을 완료했다. 실제 두 브라우저 화면 확인과 운영 배포는 남은 작업이다.

멀티 게임판의 기본 배치는 [예상 시안](../development-plan.md#멀티-게임판-시각-방향)을 참고한다.

## 작업 기록
- 구현 내용: `/game/:roomId` 멀티 게임판과 공개/개인 문서 구독을 추가했다. 상대 공개 자원, 귀족, 카드 시장, 은행, 본인 자원·예약 카드를 서버 확정 상태로 표시한다. 화면 행동은 Callable로만 제출한다. 로컬 Functions의 `roomStarted`가 방 시작 직후 초기 문서를 만든다.
- 실행한 테스트/결과: 두 인증 세션의 실시간 구독, 예약 카드 비공개, 이어지는 행동 갱신을 에뮬레이터 통합 스크립트로 확인했다. 엔진 79개와 웹 1개 테스트, 빌드, 기존 행동 API 회귀 검증을 통과했다.
- 이슈/의사결정: UI 자동화 도구 연결 오류로 두 브라우저의 실제 렌더링·클릭은 이번 작업에서 직접 확인하지 못했다. 두 독립 인증 클라이언트의 Firestore 구독과 Callable 동작을 검증했다. 공개/개인 문서 도착 순서가 달라도 혼합 버전을 표시하지 않는다.
- 실제 프로젝트 확인: `npm run dev`는 `VITE_USE_FIREBASE_EMULATORS=false`로 실제 Firebase를 사용한다. 22일차 게임 문서 조회 규칙이 실서비스에 게시되지 않아, 시작한 방에서 `/game/{roomCode}`를 열면 `permission-denied`가 발생한다. 게임 서버 Functions도 미배포라 규칙만 게시해도 초기 게임판은 생성되지 않는다. 화면에서 이 상황을 일반 연결 오류 대신 실제 서버 미연결로 안내하도록 수정했다.
- 다음 작업에 전달할 사항: 실제 `gem-arena` 프로젝트에는 25일차 Functions 트리거와 23~24일차 Callable이 배포되지 않았다. `npm run dev`로 실제 프로젝트 방을 시작해도 초기 게임 문서가 생성되지 않으므로 멀티 게임판은 준비 중으로 표시된다. 배포·운영 전 27일차 규칙 감사, 28~30일차 동시성·화면 검증, 31일차 배포 작업이 필요하다. 26일차는 재접속·기권·새로고침 상태 복구를 진행한다.
