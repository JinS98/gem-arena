## 입력·출력·예외 조건

- 입력: `validateCatalog(cards, nobles)`는 카드·귀족 배열을 받는다. 카드 비용과 귀족 요구량은 일반 보석 5색의 0 이상 정수이며 황금색 필드를 허용하지 않는다.
- 출력: `DEVELOPMENT_CARDS`와 `NOBLES`는 고정 ID의 데이터 목록이다. `getDevelopmentCard(id)`와 `getNoble(id)`는 일치하는 항목 또는 `undefined`를 반환한다. 유효성 검사 결과는 오류 경로와 메시지의 배열이며 빈 배열이면 유효하다.
- 예외: 중복/빈 ID, 잘못된 단계·보너스 색·점수, 누락/여분/음수 비용, 부족한 카드/귀족, 단계별 색 분포 오류, 잘못되거나 중복된 귀족 요구량을 검출한다. 이 단계는 순수 데이터 작업이라 인증·멱등성 검사는 해당하지 않는다.

## 작업 기록
- 구현 내용: `ColorCounts`·`Noble` 타입, 독자 수치의 카드 90장과 귀족 10명, ID 조회 함수와 데이터 유효성 검사를 추가했다. README·데이터 모델·규칙 문서에 데이터 규격을 반영했다.
- 실행한 테스트/결과: `npm test` 12개 통과(기존 보석 7개 + 카드/귀족 5개), `npm run typecheck` 및 `npm run build` 통과.
- 이슈/의사결정: 카드 수치는 단계별 8/6/4개 비용 패턴을 5색에 회전 적용한다. 귀족은 5색 중 3색의 영구 할인 3개씩을 요구하는 10가지 조합이며 모두 3점이다. 첫 타입 검사에서 `unknown` 값 좁히기 오류가 발생해 수정 후 전체 검사를 통과했다. 카드 이름·그림은 아직 없다.
- 다음 작업에 전달할 사항: 6일차에는 고정 카드 ID 목록을 단계별 셔플해 덱·시장에 배치하고 인원에 맞춰 귀족을 선택한다. 카드/귀족 데이터 자체는 읽기 전용으로 취급한다. 구매·예약·귀족 방문 및 서버 권한 검사는 후속 일차 범위다.
