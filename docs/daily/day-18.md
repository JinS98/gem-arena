## 작업 기록
- 구현 내용: `/game/demo`에 2·3·4인 인원 선택과 새 게임 시작을 추가했다. `createInitialGameState`로 인원별 은행·시장·귀족·첫 턴을 생성하고, 각 플레이어의 점수·할인·예약 수를 엔진 상태에서 표시한다. 기존 보석 획득·반환, 카드 구매·예약, 귀족 선택, 결과 화면을 새 게임에도 연결했다. 단계별 덱 맨 위 카드 예약과 합법 행동이 없을 때의 패스를 열어 모든 기본 행동을 수행할 수 있다. 결과 화면에서 같은 인원으로 새 게임을 시작할 수 있다.
- 입력·예외: 인원은 2~4명으로 제한한다. 덱이 비었거나 예약 카드가 3장이면 해당 덱 예약 버튼을 비활성화한다. 턴 완료 후에는 다음 플레이어 버튼을 누를 때까지 중복 행동을 막고, 초과 보석 반환·귀족 선택이 끝나야 진행한다. 패스는 엔진의 `hasLegalBasicAction`이 거짓인 경우에만 허용한다.
- 실행한 테스트/결과: `npm run typecheck`, `npm run build`, `npm test` 통과(엔진 74개). 새 통합 테스트는 2·3·4인 각각 초기 상태에서 15점 이상 획득, 최종 라운드, 승자 확정까지 진행하며 매 행동의 버전 증가, 보석 총량, 카드 90장의 중복 없는 보존, 보석·예약 한도를 확인한다. 브라우저에서 각 인원의 0점 시작, 은행 4·5·7개/색, 공개 카드 12장, 덱 예약 시 황금 지급과 예약 소유자, 턴 완료 시 중복 행동 차단, 다음 플레이어 진행을 확인했다. 같은 브라우저의 로컬 UI 스토어에서 2·3·4인 경기를 각각 마지막까지 진행해 15점 이상 점수와 결과 모달을 확인했다. 390px 모바일 화면에서 가로 페이지 넘침이 없는지 확인했다.
- 이슈/의사결정: 여러 사용자가 한 기기에서 차례대로 조작하는 로컬 모드다. 로컬 게임 상태는 새로고침 시 사라지고 기존 3인 연습 화면으로 돌아간다. 비공개 덱과 모든 플레이어의 상태가 클라이언트 메모리에 있는 것은 데모 한정이다. 실제 온라인 방에는 이 전체 상태를 전달하지 않는다.
- 다음 작업에 전달할 사항: 19일차 로그인·라우팅부터 실제 플레이어 신원과 방 연결을 구축한다. 서버 확정 상태, 비공개 뷰 분리, 요청 중복 처리와 재접속은 후속 일정에서 연결한다.
