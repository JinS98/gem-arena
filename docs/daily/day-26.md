## 입력·출력·예외 조건

- 새로고침과 일시적 연결 끊김은 퇴장 요청을 보내지 않는다. Auth의 로컬 지속성을 통해 같은 UID를 복원한 뒤 방 문서와 공개·본인 개인 게임 문서를 다시 구독한다. 초대 코드로 이미 참가한 방에 다시 들어오면 기존 좌석을 반환한다.
- `leaveRoom({ roomId })`은 인증된 기존 참가자만 호출한다. 대기 중에는 본인 멤버십과 준비 상태를 제거하고, 방장이 나가면 남은 참가 순서의 첫 사람에게 방장을 넘긴다. 마지막 사람이 나가면 방을 `finished`로 표시한다.
- 진행 중에는 명시적 호출만 기권이다. 서버 트랜잭션에서 방의 `forfeited` 표시와 게임 상태·공개 뷰·모든 개인 뷰를 함께 갱신한다. 보석은 은행으로 돌아가고 카드·귀족·예약 카드는 게임에서 제외된다. 기권자는 턴·승패·패스 종료 판정에서 빠지며, 한 명만 남으면 즉시 승리한다.
- 동일 UID의 퇴장·기권 재요청은 서버 전용 처리 기록에서 원래 결과를 돌려주고 게임 버전을 다시 올리지 않는다. 비참가자·잘못된 코드·종료 후 신규 기권·게임 초기화 전 기권은 거부한다. 기권자는 게임 결과를 읽을 수 있지만 행동·재참가할 수 없다.
- UID를 잃은 경우 복구하지 않는다. 연결 끊김만으로 자동 기권하거나 턴을 자동 진행하지 않는다.

## 검증 시나리오
1. 같은 UID로 방 주소를 새로 열면 멤버십과 공개·개인 상태를 다시 구독한다. 초대 코드 재입력은 기존 좌석으로 이동한다.
2. 대기실 방장 퇴장과 마지막 참가자 퇴장, 진행 중 현재 턴 참가자 기권, 보석 반환과 마지막 생존자 승리를 확인한다.
3. 비참가자·잘못된 코드·기권 후 행동을 거부하고 동일 기권 요청이 한 번만 반영되는지 확인한다.

## 완료 기준
**새로고침·퇴장 정책을 로컬 에뮬레이터와 실제 Chrome에서 검증했다.** Firestore 오프라인 재구독도 검증했다. 오프라인 화면 UX와 실서비스 배포 검증은 남았다.

## 작업 기록
- 구현 내용: Auth UID 복원과 버전 일치 구독 경로를 유지하고, 기존 참가자의 초대 코드 재입장을 기존 좌석 복귀로 연결했다. 대기실 퇴장/방장 승계와 진행 중 기권을 `leaveRoom` Callable에 구현했다. 엔진은 기권 상태와 활성 참가자 턴·승패 계산을 처리하며, 화면에는 퇴장·기권 조작과 기권 상태를 표시한다.
- 실행한 테스트/결과: 엔진 84개, 웹 닉네임 1개 테스트와 웹/Functions 타입 검사 및 빌드 통과. 실행 중인 Auth·Firestore·Functions 에뮬레이터에서 대기실 퇴장·방장 승계·마지막 방 종료·기권·중복·권한·마지막 생존자 승리를 검증했다. Firestore SDK 연결을 끊은 사이 다른 참가자가 행동한 뒤 같은 UID의 구독이 최신 버전을 받는 것도 확인했다. 기존 실시간 게임판·행동 API 회귀 스크립트도 통과했다. `verify-browser-reconnect.mjs`로 실제 Chrome에서 같은 UID의 대기실·게임판 새로고침과 저장된 닉네임 없이 초대 코드로 돌아오는 경로를 확인했다.
- 이슈/의사결정: 에뮬레이터 기본 포트가 이미 사용 중이라 `npm run test:leave-room`의 새 인스턴스 시작은 실패했다. 같은 포트에서 실행 중인 에뮬레이터에 `node apps/web/scripts/verify-leave-room.mjs`로 접속해 검증했다. Chrome 네트워크 오프라인 에뮬레이션은 기존 Firestore 연결의 끊김을 재현하지 못해 오프라인 화면 UX 검증은 남긴다. 진행 중 화면을 닫는 동작은 기권으로 취급하지 않는다.
- 다음 작업에 전달할 사항: 27일차 권한 규칙 감사에서 기권자의 결과 읽기와 행동 거부를 재확인한다. 28~30일차에 기권과 행동의 동시 경합, 오프라인 화면 UX, 두 브라우저 전체 게임 흐름을 확인한다. 실제 프로젝트에는 22~26일차의 게임 서버와 규칙이 아직 배포되지 않았다.
