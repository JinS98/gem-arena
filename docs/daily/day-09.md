## 검증 시나리오
| 입력·조건 | 기대 출력 | 실행 결과 |
|---|---|---|
| 현재 플레이어의 시장 카드 구매 | 결제 보석 은행 반환, 소유 카드·점수 증가, 같은 시장 칸 보충, 덱 한 장 감소 | 통과 |
| 황금 결제·기존 구매 카드 할인 | 결제와 점수가 일치하고 이번 카드의 할인은 다음 구매부터 적용 | 통과 |
| 본인 예약 카드 구매 | 예약 목록에서 제거, 시장·덱 변경 없음 | 통과 |
| 시장 덱 소진 후 구매 | 시장 칸 `null`, 네 칸 배열 유지 | 통과 |
| 다른 턴·`discarding` 단계·잘못된 출처·타인 예약·없는 카드 | 거부 | 통과 |
| 부족 결제·같은 카드 중복 구매 | 거부, 실패 입력 상태 변경 없음 | 통과 |
| 정상 시장 구매 후 카드 배치 | 90장 전체가 시장·덱·플레이어에 중복 없이 한 번씩 존재 | 통과 |

## 입력·출력·예외 조건

- 입력: `buyCard(state, playerId, action)`은 서버 전용 전체 상태, 현재 플레이어 UID, `BUY_CARD` 행동(`source`, `cardId`, `payment`)을 받는다. 시장 카드 또는 자신의 예약 카드만 대상이 된다.
- 출력: 기존 구매 카드의 할인으로 결제한 뒤 새 은행·플레이어 보유량·구매 카드 목록·점수와 시장/덱 또는 예약 목록을 담은 새 상태를 반환한다. 입력 상태는 변경하지 않는다. 시장 보충은 해당 단계 덱의 맨 앞 ID를 같은 칸에 놓는다.
- 예외: 현재 턴/단계가 아니거나, 카드가 출처에 없거나, 결제가 유효하지 않거나, 이미 산 카드면 `RangeError`로 거부한다. 실패 시 부분 갱신은 없다. 이 함수는 턴·버전·귀족 판정을 진행하지 않는다. 인증·멱등성·버전 검사는 후속 reducer/API 단계에서 처리한다.

## 작업 기록
- 구현 내용: 시장/예약 카드 구매 순수 함수를 추가했다. 8일차 결제를 호출하고 카드 소유·점수·보석·시장·덱·예약 목록을 함께 갱신한다. README·데이터 모델·규칙 문서를 갱신했다.
- 실행한 테스트/결과: `npm test` 40개 통과(9일차 구매 7개 포함), `npm run typecheck` 및 `npm run build` 통과.
- 이슈/의사결정: 덱 배열의 0번이 다음 보충 카드다. 빈 덱에서는 시장 칸을 `null`로 유지한다. 순수 구매 함수는 `version`과 `turnIndex`를 그대로 둔다. 귀족 방문·턴 종료·버전 증가와 API 멱등성은 후속 일차에 연결한다.
- 다음 작업에 전달할 사항: 10일차 예약 함수는 공개 카드 예약 시 같은 칸을 보충하고, 덱 맨 위 비공개 예약은 다른 플레이어에게 카드 ID를 드러내지 않아야 한다. 13일차 reducer는 구매 후 귀족 판정과 턴 완료를 연결한다.
