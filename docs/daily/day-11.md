## 입력·출력·예외 조건

- 입력: `eligibleNobleIds(state, playerId)`는 현재 공개 귀족과 구매 카드 보너스를 비교한다. 기본 행동과 초과 보석 반환 후 `resolveNobleVisit(state, playerId)`을 호출한다. 자격 귀족이 둘 이상이면 현재 플레이어만 `chooseNoble(state, playerId, { type: 'CHOOSE_NOBLE', nobleId })`을 호출할 수 있다.
- 출력: 자격자가 없으면 `turnNobleResolved: true`, 한 명이면 귀족 ID·3점 반영과 공개 목록 제거, 둘 이상이면 `phase: 'choosingNoble'`을 반환한다. 선택 후에는 한 명만 방문하고 `playing`으로 돌아가며 완료 표시한다. 모든 함수는 입력 상태를 변경하지 않는다.
- 예외: 잘못된 턴·단계, 자격 없는 귀족, 10개 초과 보석, 같은 턴 중복 방문, 잘못된 공개 귀족 목록은 `RangeError`로 거부한다. 턴·버전 증가는 여기서 하지 않는다. 인증·멱등성은 후속 API 단계에서 처리한다.

## 작업 기록
- 구현 내용: `PlayerState.nobleIds`와 `ServerGameState.turnNobleResolved`를 추가하고, 귀족 자격 검사·자동 방문·복수 선택 순수 함수를 구현했다. 구매/예약 함수도 귀족 방문 완료 후 같은 턴의 추가 행동을 거부한다.
- 실행한 테스트/결과: `npm test` 53개 통과(11일차 귀족 6개 포함), `npm run typecheck` 및 `npm run build` 통과.
- 이슈/의사결정: 귀족 자격에는 보유 보석·예약 카드를 포함하지 않는다. 귀족 방문은 턴 기본 행동이 아니라 턴 마무리 단계이며 최대 한 명이다. `turnNobleResolved`를 추가해 여러 귀족을 연속 수령하지 못하게 했다. 실제 기본 행동 후 호출 순서와 다음 턴 초기화는 13일차 reducer에서 연결한다.
- 다음 작업에 전달할 사항: 12일차 최종 라운드는 귀족 점수가 포함된 `score`를 턴 종료 시 판정한다. 13일차 reducer는 초과 보석 반환 후 귀족 판정을 호출하고, 귀족 선택 완료 후 턴 진행·버전 갱신과 `turnNobleResolved: false` 초기화를 수행한다.
