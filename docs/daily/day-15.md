## 검증 시나리오
| 조건 | 기대 결과 | 확인 결과 |
|---|---|---|
| 은행에서 서로 다른 세 색 선택 | 보석 획득, 은행·내 보유량 갱신 | 브라우저 동작 확인 |
| 한 색만 선택하거나 재고가 4개 미만인 색으로 2개 시도 | 획득 버튼 비활성화·선택 차단 | 브라우저 동작 확인 |
| 재고 4개인 파란색 두 개 선택 | 2개 획득, 은행·내 보유량 갱신 | 브라우저 동작 확인 |
| 9개 보유 상황에서 세 색 획득 | `discarding` 연습 단계, 초과 2개 표시 | 브라우저 동작 확인 |
| 초과 2개를 정확히 선택·반환 | 은행 복귀, 보유량 10개, 연습 턴 완료 | 브라우저 동작 확인 |
| 데스크톱·좁은 화면 | 은행과 조작 패널 표시 | 1440px·500px 렌더링 확인 |

## 입력·출력·예외 조건

- 입력: 사용자는 은행의 일반 보석을 눌러 서로 다른 색을 최대 세 개 고르거나, 은행에 4개 이상 있는 한 색을 골라 두 개 받는다. 초과 보석이 있으면 보유한 일반·황금 보석의 반환 수량을 고른다.
- 출력: 엔진의 `canTakeGems`, `takeGems`, `excessGemCount`, `discardExcessGems`로 검증·계산한 은행과 내 보유량을 화면에 반영한다. 한 번 획득하면 반환을 완료할 때까지 다른 획득을 막고, 완료 후에는 `처음부터` 또는 `9개 보유 상황`으로 연습을 다시 시작한다.
- 예외: 규칙에 맞지 않는 조합, 재고 부족, 초과분과 다른 반환량은 확인 버튼을 비활성화한다. 이 화면은 샘플 상태만 바꾸며 서버 확정 상태나 다른 플레이어의 자산은 변경하지 않는다.

## 작업 기록
- 구현 내용: 은행 보석 버튼·획득 방식 전환·선택 표시·초과 반환 수량 조절·연습 상태 초기화를 추가했다. `demoGemStore`에 화면 전용 은행·내 보유량·선택·단계를 보관하고 엔진 순수 함수로 상태를 갱신한다.
- 실행한 테스트/결과: `npm run typecheck`, `npm run build` 통과. 헤드리스 브라우저에서 잘못된 선택, 서로 다른 세 색, 같은 색 두 개, 9개 보유 후 획득·초과 반환을 조작해 확인했다. 데스크톱·좁은 화면도 렌더링했다.
- 이슈/의사결정: 초기 샘플 은행의 파란색을 4개로 조정해 같은 색 두 개 획득을 연습할 수 있게 했다. 한 연습 턴이 끝나면 추가 획득을 막고 명시적으로 초기화한다. Firebase 상태나 전체 `ServerGameState`를 웹에 보관하지 않는다.
- 다음 작업에 전달할 사항: 16일차 카드 구매·예약 조작은 동일한 게임판에 추가하되, 로컬 연습 상태와 실제 서버 확정 상태를 구분한다. 17일차 턴·귀족·결과 UI와 함께 여러 행동을 한 판으로 연결한다.
