## 입력·출력·예외 조건

- 방 문서는 인증된 `playerOrder` 참가자만 단일 문서로 읽는다. 방 목록과 삭제는 모두 거부한다. 생성·참가·준비·시작만 각각 정해진 필드와 상태 전이에서 허용한다.
- 생성·참가 닉네임은 2~16자이며 앞뒤 ASCII/Unicode 공백과 BOM 문자를 허용하지 않는다. 클라이언트의 `trim()` 결과를 우회한 직접 Firestore 쓰기도 거부한다.
- 공개 게임 문서는 방 참가자만, 개인 예약 문서는 해당 UID만 단일 문서로 읽는다. 기권해도 `playerOrder`에 남으면 결과를 읽을 수 있다. 대기실 퇴장으로 멤버십을 잃으면 읽을 수 없다.
- 서버 덱, 행동·퇴장 처리 기록은 모든 클라이언트 읽기·쓰기 거부다. 공개/개인 게임 문서도 클라이언트 직접 쓰기·목록 조회를 거부한다. 서버 Admin SDK만 신뢰 경로에서 쓴다.

## 권한 매트릭스

| 경로·작업 | 허용 주체 | 거부 주체·조건 |
|---|---|---|
| `rooms/{code}` 단일 읽기 | 현재 참가자·기권자 | 비로그인·비참가자·퇴장자 |
| 방 생성·참가·준비·시작 | 해당 인증 UID, 유효한 상태 전이 | 위조 방장·다른 사람 준비·미준비 시작·시작 후 참가 |
| `game/publicState` 단일 읽기 | 현재 참가자·기권자 | 비로그인·비참가자·퇴장자 |
| `privatePlayers/{uid}` 단일 읽기 | 해당 UID인 참가자 | 타인·비참가자·퇴장자 |
| `privateState/server`, `actionReceipts`, `leaveReceipts` | 서버 Admin SDK | 모든 클라이언트 읽기·쓰기 |
| 컬렉션 조회·게임 문서 직접 변경 | 없음 | 모든 클라이언트 |

## 검증 시나리오
1. 정상 방 생성·참가·본인 준비·방장 시작과 공개/본인 개인 문서 읽기를 허용한다.
2. 위조 필드, 앞뒤 공백 닉네임, 타인 준비, 미준비 시작, 비참가자 읽기, 서버 전용 문서 접근을 거부한다.
3. 시작 후 참가·준비 변경, 게임 문서 직접 쓰기·삭제·목록 조회, 기권 뒤 결과 읽기와 멤버십 제거 뒤 읽기 거부를 확인한다.

## 완료 기준
**Auth·Firestore 에뮬레이터에서 허용 14건·거부 47건의 권한 매트릭스가 통과한다.** 운영 프로젝트 규칙 게시와 배포 후 확인은 31일차 범위다.

## 작업 기록
- 구현 내용: `validPlayer`가 닉네임의 앞뒤 공백과 Unicode 구분자를 거부하도록 보강했다. 새 `verify-security-rules.mjs`는 방 상태 전이, 공개·개인·서버 전용 문서, 처리 기록, 목록 조회, 직접 쓰기, 기권·퇴장 뒤 읽기를 독립 인증 세션으로 검사한다. 기존 게임 뷰 검증은 Functions 자동 초기화와 테스트 수동 초기화가 경합해도 생성된 네 문서를 확인하도록 보완했다.
- 실행한 테스트/결과: `node apps/web/scripts/verify-security-rules.mjs`에서 허용 14건·거부 47건 통과. `verify-client-rooms.mjs`와 `verify-game-views.mjs` 회귀 검증 통과. 실행 중인 에뮬레이터의 현재 `firestore.rules`를 사용했다.
- 실패 사례·의사결정: 초기 감사에서 공백만 있는 닉네임과 앞뒤 Unicode 공백·BOM 문자가 직접 쓰기로 허용되는 것을 재현했다. 규칙과 거부 테스트를 추가해 해결했다. `verify-game-views.mjs`의 첫 재실행은 이미 켜진 Functions 트리거가 초기화를 선점해 `ALREADY_EXISTS`로 실패했으며 테스트의 경합 처리 후 통과했다. 기존 에뮬레이터가 기본 포트를 사용 중이어서 `npm run test:rules`의 새 인스턴스 실행 대신 스크립트를 직접 실행했다.
- 다음 작업에 전달할 사항: 28일차에 행동·기권 동시 요청과 응답 유실 경합을 검증한다. 실제 프로젝트에 22~27일차 규칙·Functions를 게시할 때 기존 운영 규칙을 비교하고 배포 후 권한 매트릭스를 다시 확인한다.
