## 입력·출력·예외 조건

- 행동 요청은 방 코드·`actionId`·`expectedVersion`·행동 내용을 함께 보낸다. 정상 처리 시 서버가 확정한 버전을 받고, 그 버전의 공개·개인 문서가 구독될 때까지 추가 행동을 막는다.
- 한 화면에서 연속 클릭해도 요청은 한 건만 보낸다. 대기실의 준비·시작·퇴장과 게임판의 행동·기권이 같은 잠금을 사용한다.
- Callable 응답을 받지 못한 `unavailable`·`deadline-exceeded` 상태에서는 새 행동을 막고 동일 `actionId`와 내용을 재전송한다. 서버가 먼저 확정한 버전이 구독으로 도착하면 보류 요청을 해제한다. 확정된 거부 응답은 보류 요청을 해제한다.
- 서버는 같은 ID·같은 내용의 재전송에 최초 결과를 반환한다. 같은 ID·다른 내용은 거부하고, 같은 버전의 서로 다른 행동은 하나만 확정한다. 행동과 기권이 경합해도 최종 공개·서버 상태 버전이 일치해야 한다.

## 검증 시나리오
1. 실제 Chrome 게임판에서 예약 버튼을 한 JavaScript 작업 안에 두 번 클릭하고, 서버 버전·예약 수·처리 기록이 모두 한 번만 증가하는지 확인한다.
2. 에뮬레이터에서 정상 행동 후 응답 유실을 가정해 같은 요청을 다시 보내고, 같은 응답과 버전 하나만 남는지 확인한다.
3. 같은 버전의 서로 다른 행동을 경합시키고, 행동과 기권도 경합시킨다. 성공·거부 결과, 처리 기록, 공개·서버 상태 버전과 기권 표시를 비교한다.
4. 비회원·다른 차례·불법 행동·낡은 버전·다른 내용으로 재사용한 ID를 거부한다.

## 완료 기준
**중복 클릭·응답 유실 재전송·행동/기권 경합 뒤에 처리 기록과 서버·공개 상태가 일치한다.**

## 작업 기록
- 구현 내용: `MultiplayerGamePage`와 `RoomPage`에 렌더링 전 즉시 작동하는 `useRef` 요청 잠금을 추가했다. 게임판은 응답 불명확 시 새 행동과 기권을 막고 원래 요청만 재전송하며, 최신 서버 버전 구독이 도착하면 보류 상태를 정리한다. 행동·기권 경합과 응답 유실 가정을 기존 에뮬레이터 검증에, 연속 클릭을 Chrome 검증에 추가했다.
- 실행한 테스트/결과: 실행 중인 Auth·Firestore·Functions 에뮬레이터에서 `node apps/web/scripts/verify-submit-action.mjs`, `node apps/web/scripts/verify-leave-room.mjs` 통과. Vite 에뮬레이터 모드와 격리 Chrome에서 `node apps/web/scripts/verify-browser-reconnect.mjs` 통과. `corepack pnpm --filter @gem-arena/web typecheck`, 웹 프로덕션 빌드, `npm test`(엔진 84건·웹 1건) 통과.
- 실패 사례·의사결정: 기존 화면은 `busy` 상태 변경이 렌더링되기 전의 연속 호출을 허용할 수 있었고, 응답 불명확 뒤 새 `actionId`를 만들 수도 있었다. 즉시 잠금과 보류 요청으로 해결했다. 응답 유실은 실제 네트워크 패킷 손실 대신 서버 응답을 버린 뒤 동일 요청을 재전송하는 방식으로 재현했다. 실제 서비스의 네트워크 장애와 다중 기기 동시 조작은 아직 검증하지 않았다.
- 다음 작업에 전달할 사항: 29일차에는 보류 요청·오프라인 상태의 안내와 버튼 접근성을 점검한다. 30일차에는 2~4인 E2E 진행에서 동시 요청을 다시 확인하고, 31일차 배포 후 실제 서비스에서 재검증한다.
