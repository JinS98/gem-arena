## 입력·출력·예외 조건

- `/lobby`로 이동하면 Firebase Auth의 이전 세션 복원을 기다린 뒤, 계정이 없을 때만 익명 로그인한다. React 중복 마운트도 한 로그인 요청을 공유한다. 기존 `/game/demo` 로컬 게임은 Firebase 설정 없이 계속 이용할 수 있다.
- 닉네임 입력은 앞뒤 공백을 제거한 2~16자다. 중복 닉네임은 허용한다. 저장한 값은 Auth 프로필의 `displayName`에 **방 입장 기본값**으로 유지한다. 방별 확정 닉네임은 20일차 API가 서버에 저장한다.
- 설정이 없거나 인증 연결에 실패하면 로비에 오류와 재시도 버튼을 표시한다. 닉네임이 유효하지 않으면 저장 요청을 보내지 않는다. Firestore 클라이언트 접근 규칙은 현재의 deny-all을 유지한다.
- 브라우저 저장소가 삭제되거나 익명 UID가 사라지면 기존 계정과 자리의 복구는 지원하지 않는다. Auth Emulator를 재시작하면 에뮬레이터의 사용자 데이터도 초기화된다.

## 완료 기준
**익명 UID와 닉네임을 유지한다**

## 작업 기록
- 구현 내용: 홈에서 `/lobby` 입장 경로를 연결하고, 익명 세션 복원·생성, 로그인 상태 표시, 닉네임 검증·변경·저장, 인증 실패 재시도를 추가했다. UID는 내부 인증에만 사용하고 화면에는 표시하지 않는다. README에 에뮬레이터 실행과 실제 Firebase 익명 인증 활성화 절차를 기록했다.
- 실행한 테스트/결과: `npm run typecheck`, `npm run build`, `npm test`(엔진 77개·닉네임 1개), `npm run test:emulators` 통과. Auth Emulator와 연결된 실제 Edge에서 저장 후 새로고침하여 같은 UID와 `보석 장인` 복원을 확인했다.
- 이슈/의사결정: 닉네임은 방마다 달라질 수 있으므로 Auth 프로필에는 입장 기본값만 저장한다. 화면 길이 검사는 UX용이며 20일차 방 API에서도 다시 검사해야 한다. 브라우저 자동화 도구가 실행되지 않아 설치된 Edge의 로컬 디버깅 연결로 새로고침을 검증했다.
- 다음 작업에 전달할 사항: 20일차 `createRoom`/`joinRoom`은 Auth UID와 사용자가 해당 방에 입력한 닉네임을 받아 서버에서 2~16자 검증·trim·멤버십 저장을 해야 한다. 같은 UID의 기존 방 자리는 닉네임 변경만으로 새 참가로 취급하지 않는다.
