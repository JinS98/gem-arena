# 요구사항

> **20~21일차 구현 방식:** Blaze 없이 개발하기 위해 초대 코드는 클라이언트가 생성하고 방 코드 자체를 Firestore 문서 ID로 사용한다. 제한된 규칙이 방 생성·참가·준비·시작을 검증한다. 현재 시작은 방 상태를 `playing`으로 바꾸는 단계까지이며, 아래의 초기 게임 상태·서버 검증 턴은 후속 구현 목표다.

## 1일차 MVP 범위 (2026-10-19 확정)

- 익명 로그인 후 방마다 닉네임을 입력한다. 닉네임은 앞뒤 공백을 제거한 2~16자이며, 중복 닉네임은 허용한다.
- 인증된 플레이어가 비공개 방을 만들고 서버가 생성한 초대 코드를 공유한다. 코드를 가진 인증 사용자만 대기 중인 방에 참가한다. 대기실 정원은 4명이고 게임 시작 인원은 2~4명이다.
- 방장을 포함한 모든 참가자가 준비해야 방장이 게임을 시작할 수 있다. 시작 후 신규 참가와 준비 상태 변경은 막는다.
- 게임은 2~4인 턴제로 진행한다. 보석 획득, 카드 구매·예약, 귀족 방문, 15점 최종 라운드와 동점 판정을 포함한다. 세부 규칙은 [기본판 규칙](game-rules.md)에서 정한다.
- 서버가 모든 게임 행동을 검증하고 확정한다. 참가자에게 공개 상태를 실시간 전송하고, 덱과 타인의 비공개 예약 카드는 읽을 수 없게 한다.
- 행동마다 `actionId`와 `expectedVersion`을 사용해 재전송의 중복 적용과 오래된 상태에서의 행동을 막는다.
- 새로고침이나 일시적 연결 끊김 뒤 **같은 익명 UID**로 돌아오면 기존 자리와 현재 상태를 복원한다.
- 모바일과 데스크톱에서 로비·게임판·결과를 사용할 수 있다. 결과에는 승자, 점수, 동점 판정 근거를 표시한다.

## 제외

AI, 공개 매칭, 랭킹, 친구 목록, 채팅, 관전자, 턴 타이머, UID를 잃은 익명 계정의 복구는 MVP에서 제외한다.

## 사용자 흐름

| 단계 | 사용자 입력 | 화면·서버 결과 | 주요 예외 |
|---|---|---|---|
| 1. 입장 | 익명 로그인, 닉네임 입력 | 익명 UID와 방에서 사용할 닉네임 확보 | 인증 실패, 유효하지 않은 닉네임 |
| 2. 방 생성·초대 | 방 생성, 초대 코드 공유 | 방 ID·코드 발급, 생성자를 방장으로 등록 | 코드 충돌 시 서버 재생성, 생성 실패 |
| 3. 참가 | 초대 코드와 닉네임 입력 | 대기 중인 방의 빈 자리에 참가하고 로비 표시 | 코드 오류·방 없음·정원 초과·이미 시작함 |
| 4. 준비·시작 | 각자 준비 전환, 방장이 시작 | 2~4명 모두 준비하면 초기 게임 상태와 첫 턴 표시 | 비멤버·방장 아님·인원 부족·미준비 |
| 5. 턴 진행 | 현재 플레이어가 합법적인 행동 제출 | 서버가 검증·확정한 새 버전을 모든 참가자에게 전송 | 잘못된 턴·규칙 위반·버전 충돌·중복 요청 |
| 6. 최종 라운드·결과 | 마지막 턴 완료 | 15점 도달 뒤 동일 턴 수를 마무리하고 승자·점수 표시 | 종료 후 행동 거부 |
| 7. 복귀·퇴장 | 새로고침, 재접속 또는 명시적 퇴장 | 같은 UID면 자리 복원; 대기실에서는 퇴장, 진행 중에는 기권 처리 | UID 유실 시 자리 복구 불가 |

초대 코드는 방 참가 수단일 뿐 인증 수단이 아니다. 비회원과 다른 방 멤버는 해당 방 상태를 읽거나 변경할 수 없다. 브라우저의 UI 상태는 서버 확정 상태로 다시 채운다.

## 운영 정책

- 대기실에서 퇴장하면 자리와 준비 상태를 제거한다. 방장이 나가면 남은 참가자 중 먼저 들어온 사람이 방장이 된다. 마지막 사람이 나가면 방은 종료한다.
- 게임 중 브라우저를 닫거나 연결이 끊겨도 자리는 유지된다. 자동 기권·자동 턴 진행·턴 타이머는 없다. 같은 UID로 복귀하면 현재 공개 상태와 본인의 비공개 상태를 다시 받는다.
- 진행 중 `leaveRoom`을 명시적으로 호출하면 기권한다. 기권자의 보유 보석은 은행에 반환하고, 보유 카드·귀족·예약 카드는 게임에서 제외한다. 기권자는 이후 턴·승패 판정에서 제외되며 재참가할 수 없다. 활성 플레이어가 한 명만 남으면 즉시 종료하고 그 플레이어가 승리한다. 그 외에는 남은 플레이어로 게임을 계속한다.
- 익명 UID가 유실되면 기존 자리의 소유권을 증명할 수 없으므로 복구하지 않는다. 진행 중인 방에도 새 UID로 참가할 수 없다. 타임아웃이 없는 게임은 남은 플레이어가 기권하지 않으면 정체될 수 있다.
- 게임 종료 후 결과는 읽을 수 있지만 추가 게임 행동은 거부한다.

## 성공 기준

1. 별도 브라우저 2~4개에서 방 생성·참가·준비·시작·전체 게임·결과까지 완료한다.
2. 비멤버와 다른 플레이어가 서버 전용 덱·타인의 비공개 예약을 읽지 못한다.
3. 잘못된 턴, 잘못된 행동, 중복 `actionId`, 오래된 `expectedVersion`이 게임 상태를 중복 변경하지 않는다.
4. 같은 익명 UID로 새로고침한 플레이어가 기존 자리와 현재 게임 상태를 이어받는다.

현재 코드는 화면 미리보기와 보석 규칙 일부만 구현했다. 이 문서는 구현 목표이며 완료된 기능 목록이 아니다.
